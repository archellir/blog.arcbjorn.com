# Repository Guidelines

## Project Structure & Module Organization

- `routes/` Fresh routes (`index.tsx`, `[id].tsx`, `_error.tsx`, API endpoints).
  Prefer nested routes as folders with `index.tsx`.
- `components/` Preact components (PascalCase.tsx). `islands/` interactive
  islands only.
- `api/` server-side data helpers (e.g., `listPosts.ts`, `loadPost.ts`,
  `renderMarkdown.ts`).
- `data/posts/` Markdown sources with front matter. `static/` public assets.
- `assets/` stylesheets (Tailwind v4 entry plus one file per concern); bundled
  via Vite from `client.ts`. Colours come from the palette variables in
  `base.css`.
- `_fresh/` is generated by `vite build` — do not edit.
- `tests/` Deno tests. Other shared code in `utils/`, `types.ts`.

## Build, Test, and Development Commands

- `deno task dev` — run locally with Vite (HMR).
- `deno task build` — build server and assets into `_fresh/`.
- `deno task start` — start the production server.
- `deno task test` — run Deno tests.
- `deno task check` — format check, lint, and type-check.
- `deno task update` — update Fresh; `deno outdated` lists the rest.

## Coding Style & Naming Conventions

- Language: TypeScript (TS/TSX). Avoid `any`; prefer explicit types.
- Formatting: `deno fmt`; Linting: `deno lint` (configured via `deno.json`).
- Files: components in PascalCase (`BlogLayout.tsx`); routes use path-style
  names (`sitemap.xml.ts`, `[id].tsx`).
- Symbols: camelCase for functions/vars; UPPER_SNAKE_CASE for constants; hooks
  as `useX`.
- Imports: use `fresh` (core) and `fresh/runtime` for `Head`; `@std/*` and
  `@deno/gfm` from JSR and npm packages, all mapped in `deno.json`. Nothing
  comes from deno.land/x or esm.sh.

## Testing Guidelines

- Framework: Deno test with `@std/assert` and BDD from `@std/testing/bdd`.
- Location: `tests/` or colocated as `*_test.ts`.
- Scope: cover `api/` helpers and route handlers (happy paths + error cases).
- Run: `deno task test` and ensure `deno task check` passes before pushing.

## Commit & Pull Request Guidelines

- Conventional Commits; one focused change per commit; subject ≤ 50 chars.
  - Examples: `feat: paginate posts on index`, `fix: handle missing post file`.
- PRs: clear description, linked issues, before/after screenshots for UI
  changes, and notes on tests/coverage. Avoid unrelated refactors.

## Security & Configuration Tips

- Never commit secrets; the site needs no environment variables.
- Static caching is configured in `main.ts`; keep cache headers in mind for new
  assets.
- Do not modify generated `_fresh/` output; regenerate via
  `deno task build`/`update`.
